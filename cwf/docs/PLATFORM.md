# Platform assumptions and verification

Official opencode documentation checked when CWF was retargeted to opencode (2026-11-12, OpenCode V2 pages):

- https://opencode.ai/docs/skills/ -- global skills are discovered under `~/.config/opencode/skills` and the compatibility roots `~/.claude/skills` and `~/.agents/skills`; project skills under `.opencode/skills`, `.claude/skills` and `.agents/skills`, searched from the current directory up to the project root. The skill ID comes from the file path; the frontmatter `name` is a display label. Duplicate IDs are not merged: a later-registered source overrides an earlier one, and `~/.config/opencode/skills` and project `.opencode/skills` register after `~/.agents/skills`. The model loads a skill through the `skill` tool with its exact ID; a user names one as `@skill-id`. `permissions` rules with `"action": "skill"` allow, ask or deny by ID. CWF links namespaced `cwf-<domain>` directories into `~/.agents/skills` and checks collisions in that directory only. The page does not say whether symlinked skill directories are followed.
- https://opencode.ai/docs/instructions/ -- global guidance is `~/.config/opencode/AGENTS.md`, loaded before every `AGENTS.md` from the workspace directory toward the home directory. Sources are combined rather than used as overrides; there is no override file, and V2 does not fall back to `CLAUDE.md`. `instructions` entries in `opencode.json` load after the `AGENTS.md` files. CWF's optional owned block goes into the global `AGENTS.md`.
- https://opencode.ai/docs/config/ -- global `~/.config/opencode/opencode.json(c)`, then project, then system and managed configuration. CWF does not read, replace or reformat `opencode.json`. No environment variable that relocates the config directory is documented there; `opencode debug paths config` (https://opencode.ai/docs/cli/) prints the directory in use, and `--config-root` points CWF at it.

These are documented assumptions, not live-client qualification. Current documentation may differ from the installed opencode version, and the V1 pages differ from the above (V1 falls back to `CLAUDE.md`). Plugin distribution is a documented option (https://opencode.ai/docs/plugins/); this pilot deliberately uses a reviewed local installer to support the requested per-computer rollout without a marketplace/service dependency.

CWF does not depend on plugins, lifecycle hooks or special APIs. Model selection of a skill remains probabilistic; a short global instruction is guidance, not enforcement. Terminal and IDE sessions, custom config roots, managed installations, and discovery through the installed skill links must be checked on each pilot environment. Doctor reports live visibility/behavior as NOT_TESTED rather than inferring it from file existence.
